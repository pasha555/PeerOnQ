# PeerOnQ

Secure remote-access platform. This workspace holds the PeerOnQ frontend prototype plus the
scaffolding (API skeleton, DB layer, generated API client) for the real product.

## Run & Operate

- `pnpm --filter @workspace/peeronq run dev` — frontend prototype (needs `PORT` and `BASE_PATH`;
  the artifact config supplies `PORT=23586`, `BASE_PATH=/`)
- `pnpm --filter @workspace/peeronq run test` — vitest suites
- `pnpm --filter @workspace/api-server run dev` — build + start the API (requires `PORT`, 8080 in prod)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `PORT` + `BASE_PATH` (peeronq dev/build), `PORT` (api-server),
  `DATABASE_URL` (only when `lib/db` is imported)
- Optional env: `VITE_PEERONQ_API_BASE_URL`, `VITE_ENABLE_DEMO_DATA`

`npm` and `yarn` are blocked by the root `preinstall` script. Always use pnpm.

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Frontend: React 19, Vite, TailwindCSS v4, shadcn/Radix, wouter, framer-motion,
  react-hook-form + Zod, TanStack Query, vitest
- API: Express 5 + pino, bundled with esbuild (`artifacts/api-server/build.mjs`)
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from `lib/api-spec/openapi.yaml`)

## Architecture decisions

- The PeerOnQ app is a **prototype with no backend**: repositories in `src/features/*` persist to
  `localStorage`, and `src/services/apiClient.ts` returns `NotConfigured` unless
  `VITE_PEERONQ_API_BASE_URL` is set. A test (`src/test/noNetworkRequest.test.ts`) enforces this.
- `src/repositories/index.ts` is just a barrel over the feature repositories, so features stay
  self-contained while consumers keep a single import path.
- `lib/api-client-react` and `lib/api-zod` are generated by Orval; the OpenAPI spec is the only
  place to change the contract.
- Only `/` and the 404 route render outside `AppShell`; everything else goes through `ShellWrapper`
  in `src/App.tsx`.
- `pnpm-workspace.yaml` sets `minimumReleaseAge` (1 day) as supply-chain protection. Do not disable it.

## Product

Frontend prototype covering: marketing landing page, dashboard, remote access (connect form),
devices, session history, file transfer (layout only), address book, security center, settings,
downloads, pricing, about, privacy, terms. Light/dark/system theming throughout.

## User preferences

- Keep docs and maps up to date in the same change that touches the code.
- Prefer small, reversible patches over rewrites.

## Gotchas

- `artifacts/mockup-sandbox` contains a near-identical `src/components/ui/` tree — make sure you
  are editing `artifacts/peeronq`.
- `lib/db/src/index.ts` throws at import time when `DATABASE_URL` is unset, so importing
  `@workspace/db` anywhere pulls in that requirement.
- `artifacts/api-server` `dev` runs a build first; it will not hot-reload TypeScript changes.
- Sidebar active state uses `location.startsWith(href)`, so nested routes highlight their parent.
- Tailwind v4 reads tokens through `@theme inline`; renaming a CSS variable silently breaks classes.
